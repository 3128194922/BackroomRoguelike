# Backroom Roguelike 实现设计

## 目标

把 `BackroomRoguelike` 从 Forge 示例工程补成可运行的 Minecraft 1.20.1 后室搜打撤模组。房间、玩家规则、倒计时、进入和撤离由本项目实现。KubeJS 项目仅供只读参考方块定义和数据，不在本次修改范围内；本项目不提供旧 KubeJS 维度或维度切换桥接。

## 用户已确定的要求

- 只修改 `E:\Server_mod\BackroomRoguelike` 主项目，不改参考 KubeJS 项目。
- 39 个 lock 对应 39 个不同的密码房；陶片 ID 与其方块实体 NBT 原样保留，不替换、不重写。
- 正式后室维度 ID 使用 `backroomroguelike:backroom`；39 个密码房放入独立文件夹子池，通过目录层级参与随机抽取。每次进入获得与上次不同且相距较远的起始区块区域。
- 每位玩家从进入后室时单独开始 20 分钟计时；增加可右键进入后室的道具。
- 新增撤离点方块及其 16×16×16 撤离结构模板；作为随机结构放在密码房子池中。
- 不保证每个玩家区域内一定生成撤离点；新增扫描道具寻找撤离点结构，并提供可复用的通用房间定位接口。
- 个人计时按现实经过时间持续；离线期间到期的玩家在重连时掉落背包并结束本局。
- 撤离读条期间，玩家与撤离方块距离须不超过 4 格；在后室内重复使用进入道具不重置计时或重新分配区域。
- 每个可生成房间占一个 16×16 区块单元，NBT 尺寸及地基为 16×16，房间主体缩至 15×15；模板从区块原点放置，不额外偏移。原房门轴在 15×15 房间中心，纵向高度保持 16 格，净空高度沿用原结构。
- `structures_old/` 中的房间主体和 `structures/locks/` 中的 39 个锁模板保留原方块 ID，包括 KubeJS `rainbow:*` 方块；KubeJS 是这些运行时方块 ID 的必需依赖，不映射成原版方块。
- 保留 `create:placard`、所有原版/模组铁门、Lootr 箱子和其 NBT 内容。
- 使用 Forge 1.20.1 / Java 17，不添加未获准的第三方依赖；KubeJS 与结构方块来源模组列为运行依赖；Java 包路径及 mod id 不得包含 `example`。
- 房间按区块单元放置，玩家可破坏/放置限制为冒险模式；20 分钟倒计时在屏幕上方居中显示到毫秒；死亡或超时仍留在后室时强制掉落物品。
- 单人撤离后结束该玩家本局；多人仍在后室时不影响其他玩家；每次新进入分配新的远距离区块区域，不覆盖之前生成的房间。

## 现有资源与适配

- 主项目 `structures/` 有 20 个大模板（17×16×17）；39 个 1×2×2 lock 原件位于用户指定 KubeJS 参考项目的 `data/backroom/structures/`，已只读复制到主项目 `structures/locks/`。`password_room.nbt` 是唯一需合并 lock 的基底；39 个锁各含 Create 展示框和不同陶片。
- 为避免破坏原件，主项目大模板和锁原件副本均保留不改；外部 KubeJS 项目不写入。最终运行时房间另存为本模组命名空间下的资源，分为 18 个普通房模板、39 个合成密码房和 1 个撤离结构。`sweet_roll.nbt` 是测试遗留房，不作为随机房间。
- 合成过程以 `structures_old/password_room.nbt` 为基底，把每个 lock 按对应 jigsaw 朝向/位置放入；移除用于 Jigsaw 拼接的控制方块，将 17×16×17 原模板裁为 15×16×15 的房间主体，保留 y=0 的 16×16 地基，并将 NBT 尺寸设为 16×16×16。生成时从区块原点写入，不加偏移；修整需保留各方向走廊开口、房间中轴上的门、展示框朝向、箱子及其内容。
- 原始大模板在 y=6..15 含有十层 `minecraft:bedrock` 临时填充。正式维度独立在 minY（-64）生成唯一一层基岩边界；运行时房间删除这十层填充，保持 16 格结构高度和室内净空。
- 将正式维度、维度类型、生物群系和结构放到 `data/backroomroguelike/` 命名空间，唯一支持的后室维度键为 `backroomroguelike:backroom`。不创建 `backroom:backroom` 兼容维度，不接管或重定向旧 KubeJS 维度传送；本模组进入道具直接进入正式维度。
- 将运行时房间放在 `data/backroomroguelike/structures/rooms/` 作为池根目录：18 个普通房 `.nbt` 直接放在根目录；39 个密码房变种和 1 个撤离结构 `.nbt` 直接放在其 `password/` 子目录。结构池读取器递归枚举目录；每层把直接 `.nbt` 文件和直接子目录作为同级候选等概率抽取，抽到子目录时递归，直到抽到一个 `.nbt`。原始小锁和其他不参与生成的 NBT 放在池根目录之外。
- 按规范化区块坐标的稳定哈希确定房间和朝向，使同一区块生成与扫描预测完全一致；世界种子用于初始区域分配，持久化分配序号保证服务器重启后不会复用旧区域。新局使用新的区块区域而不是改写旧布局。
- 根目录共有 18 个普通房文件和一个 `password/` 子池，因此密码房子池总抽取率为 1/19。密码房子池里有 40 个等概率模板（39 个密码房 + 1 个撤离结构），单个房间区块抽到撤离结构的概率为 1/760；以后增删根文件、子目录或池内模板会自然改变概率。
- 通用定位器使用与区块生成相同的坐标哈希和递归池选择规则，预测目标结构的区块坐标，不为搜索提前加载区块；扫描道具默认在 128 区块半径内定位最近的撤离结构并在聊天栏给出坐标与距离，搜索分批执行以避免阻塞服务端 tick。公共 API 接受房间资源 ID/类型及搜索半径，返回最近候选位置，供后续模组功能复用。

## 模组结构与玩家流程

1. 将 MDK 示例 mod id、显示名、Gradle group 和 Java 包迁移为 `backroomroguelike` / `com.servermod.backroomroguelike`，移除示例方块、物品、配置和日志代码。正式数据包命名空间及唯一支持的维度 ID 使用 `backroomroguelike` / `backroomroguelike:backroom`；不提供 KubeJS 旧维度的兼容资源或重定向逻辑。
2. 迁移后室维度、维度类型、生物群系及所需数据包资源到本模组。正式维度底部只生成一层基岩边界，位于世界最小 Y（默认 -64）；房间按区块地表高度生成，玩家落点也从地表计算。
3. 玩家右键使用进入道具时，若尚未处于正式维度，服务端直接传送至 `backroomroguelike:backroom` 的个人区域，开始该玩家自己的 20 分钟倒计时。道具可重复使用且使用时不消耗；玩家已在正式维度时忽略再次使用，不重置计时或区域。
4. 正式维度使用本模组自定义 `ChunkGenerator`，在原版 `fillFromNoise` 区块生成回调中先生成位于世界最小 Y 的单层基岩边界，再按区块地表高度确定结构原点，递归抽取模板并直接写入 `ChunkAccess`；房间地基贴合表面，方块实体 NBT 也在生成阶段写入区块。该回调不读取玩家会话 `SavedData`，因此每次玩家开局由服务端持久化分配一个全新的远距离起始区域；结构选择只依赖规范化区块坐标，使扫描器能在不加载区块时预测同一结果。模板 NBT 尺寸为 16×16×16，主体占 15×15，生成时不偏移；玩家落点从生成后表面高度计算。已生成区块由原版区块保存机制持久化，不在普通加载时再次放置。
5. 在倒计时期间将非创造玩家置为冒险模式；服务端拦截放置、破坏及能改变后室方块的爆炸/火焰类事件。房间内开门、开箱和战斗仍可交互。
6. 客户端 HUD 为每位玩家在屏幕上方居中显示独立剩余时间，使用服务端时间差、每 tick 同步/刷新，格式精确到毫秒。
7. 每个房间区块从递归池规则中选择结构；撤离结构作为 `password/` 池中的一个候选模板，因此随机散布在后室区域。玩家找到撤离方块并在 4 格范围内右键后开始 10 秒读条，受伤或距离超过 4 格时中断。成功后传送回主世界并恢复生存模式，不清空物品。
8. 扫描道具按玩家本次分配的区块区域寻找最近的撤离结构，不保证每个区域都有出口；定位结果显示目标区块/坐标和距离。提供公开的 `RoomLocator` API，调用方可传入目标房间资源 ID/类型查找其他房间。定位预测不得加载目标区块；玩家到达后由同一个 `ChunkGenerator.fillFromNoise` 选择器生成该结构。
9. 后室死亡或个人 20 分钟到期时，服务端在死亡前将玩家背包物品强制生成掉落实体并清空原槽位，然后结束该玩家本局；物品留在死亡/超时地点，玩家按原版规则在主世界重生。计时以持久化的现实时间戳计算，断线不暂停；若玩家离线期间到期，在其重连、回到后室时先掉落物品并结束本局。避免与原版死亡掉落重复。多人共局中，单人死亡只移除该玩家的运行状态；仍有玩家时不重置布局。在线/离开判断以维度玩家集合为准。
10. 玩家离开后结束其个人区域占用；下一次进入始终分配一个新的区域，不复用旧区块，避免改写或清理既有结构。每位玩家在同一时段仍被分配到互相远离的区域；持久化的区域分配序号确保服务器重启后也不会重复分配。

## 结构生成实现依据

- 参考 `C:\Users\Uniye\AppData\Roaming\.minecraft\versions\地下酒吧\mods\structrealm-1.0.0.jar` 中的 `FlatStructureChunkGenerator`：结构生成发生在 `ChunkGenerator.fillFromNoise(...)`，按区块坐标选择模板并直接对 `ChunkAccess` 写方块状态/方块实体；初次区块生成不依赖 `ChunkEvent.Load` 等 Forge 游戏事件。
- 模组会注册自定义 ChunkGenerator codec，并在维度 JSON 中引用该生成器。结构模板在资源重载时解析为不可变目录池，供异步区块生成线程安全读取。
- 本项目不采用参考模组对特定传送门的 `entityInside` 触发、手动 `ServerLevel` 放置和 `PortalSavedData` 去重逻辑；本项目的房间属于区块世界生成，已生成内容随原版区块保存。

## 边界

- 不修改 KubeJS 项目，也不兼容或桥接其旧维度/传送路径；本模组的进入道具直接进入 `backroomroguelike:backroom`。KubeJS 目录仅作为资源分析参考。
- Java 完整负责本模组的房间分配、进入、局内管理和撤离。
- 不调整陶片、Lootr 箱内容、陶片物品 ID、门种类或门的 block entity 数据。
- `sweet_roll.nbt` 不进入随机房间池；其测试用途原件仍保留。
- 追猎者、战利品经济再平衡、Curios/Backpacked 专属槽位的兼容性不在本次实现范围，除非用户另行确定。
- 不添加新第三方库或模组依赖。结构读取、客户端 HUD、网络同步和数据持久化使用 Forge/Minecraft API。

## 验收标准

- ForgeGradle 编译成功，运行时资源能被本模组加载；加载日志能指出结构资源缺失/非法文件。
- 唯一支持的后室维度 ID 为 `backroomroguelike:backroom`；本模组不注册 `backroom:backroom` 维度，也不提供旧 KubeJS 传送桥接。
- 随机池按目录层级递归工作；根目录普通模板与子目录同级等概率，密码池内 39 个变种及撤离结构等概率，嵌套子目录可以继续形成子池。
- 扫描道具能在默认搜索半径内定位当前局最近的撤离结构（包括尚未加载的区块），公共 `RoomLocator` API 能按资源 ID/类型和指定半径定位其他房间，且扫描过程分批进行、不加载目标区块。
- 运行时房间资源中每个 NBT 的 `size` 都为 `[16,16,16]`；房间主体为 15×15、y=0 地基为 16×16，门位于 15×15 房间中轴；39 个密码房各保留其对应 lock 的陶片 ID、`create:placard` NBT 与门。
- `rainbow:*` 方块、Lootr 箱子、门和 Create 展示框按源 NBT 保留；输出不含结构拼接 jigsaw 控制方块。
- 相邻区块房间的四向走廊开口能连续通过，房间不会写入相邻区块的单元之外；基岩边界固定在最小 Y，房间地板和玩家站立位置跟随地表高度。
- 每个分配区域的布局按稳定坐标哈希生成；根文件、子池及嵌套子池按目录规则抽取；多人共局互不覆盖，每次后续进入获得新的区域，已生成区块不被重写。
- 冒险限制、每人独立倒计时 HUD、离线继续计时、4 格内 10 秒撤离读条及受伤/超距中断、成功撤离保留物品、死亡/超时掉落并且不重复掉落均可用；进入道具可重复使用且不消耗，局内重用不重置。

## 留给实现者的细节

- 从 `structures_old/` 重建运行模板：房间主体裁为 15×15、y=0 地基保留 16×16，NBT size 保持 16×16×16；按门位置核对中轴并保证不做生成偏移。
- 自定义 ChunkGenerator 的 codec、结构目录池资源重载时序和玩家区域分配均需按 Forge 1.20.1 API 实现；结构放置不得依赖 `ChunkEvent.Load`。
- 对 `netherexp:*` 陶片保持 NBT ID 不变；已提供的模组目录似乎未含 NetherExp，因此这些陶片要在运行实例装有该模组时才能正常解析/显示。
- KubeJS 仅用于提供模板引用的 `rainbow:*` 方块注册；不实现旧维度入口、传送兼容或安全着陆桥接。本模组使用自己的进入道具和撤离点。
